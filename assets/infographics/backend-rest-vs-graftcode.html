Key differences
Concern Classical REST Graftcode
Contract OpenAPI / docs + manual HTTP client Typed package: @graft/nuget-EnergyPriceService
Call style HTTP request + JSON parse Native method: BillingLogic.CalculateMonthlyBill(...)
Errors HTTP status codes + custom mapping Native exceptions propagate to caller
Transport HTTPS, verbs, headers, serialization Hypertube over TCP / WebSocket (IIP binary protocol)
Provider surface Controllers, routing, DTOs, middleware Public methods only; GG hosts the module
Config switch Change URLs, clients, env vars Change GraftConfig.host only

REST call stack

  1. fetch / HttpClient
  2. URL + query string construction
  3. HTTP routing & middleware
  4. Controller dispatch
  5. JSON deserialize → DTO
  6. Map DTO → domain model
  7. Business logic executes
  8. DTO → JSON response

Graftcode call stack

  1. BillingLogic.CalculateMonthlyBill(...)
  2. Graft captures invocation intent
  3. IIP message over Hypertube (TCP)
  4. GG loads .NET runtime
  5. Business logic executes
  6. Result marshalled to caller types
Same code, different transport. Graft consumer code is identical whether called from React or Node.js — only GraftConfig.host changes: wss:// for browser clients, tcp:// for backend-to-backend inside your network.
